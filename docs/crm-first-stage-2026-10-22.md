# CRM: первый этап исправлений

Дата: 22 октября 2026 года. Основа: `crm-audit-and-plan-2026-10-22.md`, пункты A01–A07. Изменения только во frontend, без изменения серверных контрактов.

## Что реализовано

| Пункт | Изменение |
| --- | --- |
| A01 | Начальные данные формы устанавливаются один раз. Загрузка услуг больше не восстанавливает старые значения поверх ручных изменений. Первый выбор продажи сохраняет материал, объём, единицу, объект и примечание лида. |
| A01 | Адрес очищается только при фактической смене соответствующей компании или переходе на самовывоз. Повторный выбор текущего значения не сбрасывает поля. Перевозка включает доставку и очищает несовместимые цены продажи/закупки, сохраняя остальные данные. |
| A01 | При редактировании существующей сделки услуга и заказчик зафиксированы: текущий PATCH-контракт исключает эти поля. Переключение услуги доступно при создании. |
| A02 | У каждой доставки сохраняется и отображается собственная `unit`. Она используется и в preview, и при сохранении. При наличии сохранённых доставок или новых фактических доставок смена общей единицы заблокирована. |
| A03 | Расчёт имеет состояния загрузки и ошибки с повтором запроса. Изменение исходных данных сразу скрывает предыдущие суммы, включая время задержки запроса. Поздние ответы не заменяют новый результат. Кнопка сохранения остаётся доступной по прежним правилам заполнения формы. |
| A04 | Обе формы адресов проверяют заполненность координат и диапазоны: долгота от -180 до 180, широта от -90 до 90. Явно введённый ноль разрешён, пустое значение не заменяется нулём. Десятичная запятая поддерживается. |
| A05 | Сортировка и максимальная цена доступны только для одного материала и одной единицы. Для нескольких единиц требуется выбор. Алиасы вроде «т»/«тонна» сопоставляются, пересчёта тонн в м³ нет. Географический фильтр не подменяет явно выбранную единицу. |
| A06 | Смена фильтра сделок сбрасывает страницу до первого запроса. Сохранённые фильтры применяются сразу. Ошибки загрузки видны в таблице и канбане, доступен повтор. Ответы устаревших запросов отбрасываются. После смены этапа обновляется текущий запрос, а не старый снимок фильтров. |
| A07 | Пустая, некорректная и отрицательная цена не сохраняется. Явный ноль разрешён, поскольку контракт не требует строго положительную цену. Очищенный комментарий отправляется пустой строкой, а не пропускается. |

## Автоматические проверки

- `npm test`: проверка TypeScript для исходников и тестов, затем Vitest. 46 тестов в пяти файлах проходят.
- Тесты включают перевод лида в сделку через форму, сохранение исторических доставок, позднюю загрузку справочника, ошибку preview с повтором, сброс пагинации, поздние ответы, валидацию обеих форм адресов и PATCH очищенного комментария.
- Запросы в тестах подменены контролируемыми ответами. Тесты не создают и не меняют реальные данные.
- `npm run build`: проходит; остаётся предупреждение о размере общего JS-чанка.
- ESLint на изменённых исходниках, конфигурации и тестах: проходит.
- Исправлен запуск ESLint: совместимый AJV для его зависимостей, исключены сгенерированные каталоги `.next`, `dist`, `coverage`. Прикладные зависимости не обновлялись; добавлены тестовые зависимости и согласованы оба lock-файла.
- Общий `npm run lint` выявляет 14 прежних ошибок в админке, форме входа, типах update-запросов и файле канбана. Они не подавлены и не входят в текущие функциональные исправления.

## Что ещё проверить

1. Авторизованный сценарий на тестовом backend: лид с объектом и объёмом → сделка → доставка → редактирование → повторное открытие. В браузере локальное приложение открывает экран входа; живой E2E и адаптивная визуальная приёмка не выполнены.
2. Применить аналогичные ограничения на сервере: запрет незаметной смены единиц фактических доставок, валидация координат и цен. Frontend не заменяет серверную валидацию.
3. Согласовать, должно ли сохранение блокироваться при недоступном preview. Сейчас старые суммы скрыты, но прежняя возможность сохранения не менялась.
4. A08: серверный поиск связанных сделок. Подтверждённого контракта для его реализации по-прежнему нет.
5. Следующий функциональный этап плана: рабочий стол сотрудника на существующих задачах и лидах. Платежи, самостоятельные поставки и расширенные права не реализовывались.

Во время работы появилась неиспользуемая копия `hook 2.tsx`, побайтно совпадающая с исходным hook в HEAD. Содержимое сохранено без изменений в `docs/backups/deal-form-hook-before-fixes.tsx.txt`, чтобы резервная копия не участвовала в компиляции.
