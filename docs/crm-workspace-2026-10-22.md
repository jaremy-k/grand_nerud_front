# CRM: рабочий стол и серверный API

Дата: 22 октября 2026 года. Продолжение этапа 2 из аудита.

## Реализовано

- Вместо перенаправления главной страницы открывается рабочий стол. После входа пользователь также попадает на него; старый маршрут /dashboard перенаправляет на главную.
- Четыре показателя: просроченные задачи, задачи сегодня, предстоящие задачи и новые лиды. Числа берутся из серверного total, а не из количества загруженных строк.
- Короткие списки содержат до шести записей. Задачу можно открыть или завершить с результатом; лид и связанную сделку можно открыть напрямую. Создание лида и задачи использует существующие формы.
- По умолчанию показываются свои записи. Руководитель и администратор могут явно выбрать команду или сотрудника. Обычный пользователь не получает чужой ownerId из URL в запросах; сервер независимо запрещает чужую и командную выборку.
- Фильтры лидов и задач хранятся в URL. Показатели рабочего стола открывают списки с теми же корзиной/состоянием и сотрудником. Добавлен фильтр состояния лидов.
- Загрузка, отсутствие записей, отсутствие совпадений и ошибка разделены. Ошибки не показываются как нулевые показатели, старые ответы не подменяют новую выборку.
- Компании и адреса вынесены в группу «Компании и объекты». Вход «Воронки» объединяет навигацию к двум отдельным справочникам этапов, не объединяя их данные.

## Backend

Репозиторий: /Users/germankuceravenko/PycharmProjects/grand_nerud.

Добавлены авторизованные роуты:

~~~http
GET /workspace/tasks?scope=mine&ownerId=USER_ID&timezone=Europe/Moscow&limit=6
GET /workspace/leads?scope=team&timezone=Europe/Moscow&limit=6
~~~

- /workspace/tasks возвращает overdue, today и upcoming. Счётчики и строки считаются одним MongoDB facet с общей границей времени. Сортировка: срок и ID по возрастанию.
- /workspace/leads возвращает newLeads. Отбор идёт по kind=new активного этапа; сортировка по времени создания и ID по убыванию.
- У каждого блока есть items, total и hasMore. Общие поля: generatedAt, localDate, timezone, scope, ownerId и limit.
- scope=team доступна только руководителю/администратору. По умолчанию даже руководитель видит свои записи. Чужой ownerId и командная область у обычного сотрудника возвращают 403.
- Сохраняются проверки доступа к связанным записям задач. Внутренние поля конвертации лида не выдаются. Связанные компания и лид задачи представлены краткими публичными объектами.
- Сбой MongoDB возвращает ошибку, а не нулевой успешный результат. Ответы запрещены к кешированию через Cache-Control: no-store.

Полный контракт: [workspace.md](/Users/germankuceravenko/PycharmProjects/grand_nerud/docs/workspace.md).

Frontend рабочего стола использует именно эти два роута, без отката к старым спискам при 404. Полные списки и изменение задач продолжают использовать существующие /tasks и /leads. API_URL и настройки авторизации не менялись.

Просроченная сегодня задача входит и в overdue, и в today. Эти счётчики не складываются в общий итог. Показатели без первого контакта, без активности, конверсия и финансовые KPI не добавлялись без подтверждённых серверных данных.

## Проверки

- Backend: 192 теста проходят, включая 38 новых проверок workspace. Проверены права, схемы и HTTP-роуты, часовые пояса, переход суток/DST, сортировки/лимиты агрегаций, полные счётчики, ошибки базы и сериализация.
- Frontend: 75 тестов проходят вместе с проверкой TypeScript. Проверены новые URL запросов, отсутствие отката к прежним API, права выбора, переходы в списки, серверные total, частичный сбой блоков и завершение задачи с обновлением данных.
- Production-сборка проходит. Остаётся прежнее предупреждение о размере общего JS-чанка.
- ESLint изменённых файлов проходит; прежние общие ошибки линтера вне этого этапа не исправлялись.
- На отдельном стенде с тестовым API проверены desktop и мобильная ширина 390 px. У мобильного рабочего стола ширина контента равна viewport, переполненных ссылок и кнопок не обнаружено. Стенд не обращается к рабочему backend и не читает токены.

Backend-тесты используют подменённые коллекции MongoDB; полноценная интеграционная приёмка с реальным MongoDB и авторизованными пользователями остаётся отдельной проверкой. Развёртывание и перезапуск рабочего backend в рамках этой задачи не выполнялись: новая версия API должна быть запущена прежде, чем проверять её через рабочий frontend.
